# Lesson Plan: DOCX Export and CSV Import — Implementation Plan

Status: **Plan only. No code written yet.**

## 1. Goals

1. **Export**: a teacher or admin downloads any lesson plan they can view as a `.docx` file (English or Arabic/RTL). The file opens in Word and in Google Docs.
2. **Import**: a teacher uploads a CSV of lesson plans, previews validation results, then commits. Valid rows become draft lesson plans.

Out of scope for now: direct "Open in Google Docs" (needs the `drive.file` scope and re-consent), DOCX import, bulk ZIP export.

## 3. Feature A — DOCX export

### 3.1 API

`GET /api/lesson-plans/:id/export.docx?lang=en|ar`

- Same permission guard as `GET /:id` (so teachers can only export their own plans, admins/department principals within scope).
- Place the route **before** `/:id` is fine since the suffix differs, but keep it next to `GET /:id`.
- Response: `Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `Content-Disposition: attachment; filename="<safe-title>-<yyyy-mm-dd>.docx"` (sanitise the filename, support UTF-8 via `filename*=`).
- `lang` defaults to the user's saved email-language preference, else `en`.
- Errors: 404 if not found / out of scope, 400 for bad `lang`.

### 3.2 Server files

| File | Purpose |
|---|---|
| `services/lessonPlanDocxService.js` (new) | `buildLessonPlanDocx(plan, { lang, schoolName, teacherName, className, subjectName, standards })` → `Buffer` via `Packer.toBuffer` |
| `utils/lessonPlanDocxLabels.js` (new) | EN/AR label dictionary (headings, field names) |
| `controllers/lessonPlanController.js` | `exportLessonPlanDocx`: load plan with populate (class, subject, teacher, standards, objective standards), call service, stream buffer |
| `routes/lessonPlanRoutes.js` | register the route |

### 3.3 Document layout

1. **Header**: school name, "Lesson Plan" / "خطة الدرس" title.
2. **Info table (2 columns)**: Teacher, Class, Subject, Date, Week, Topic, Status.
3. **Sections** (skip any that are empty):
   - Summary / description
   - Previous knowledge
   - Teaching objectives and Learning objectives
   - Objectives list (numbered, with linked standard codes)
   - Vocabulary
   - Character-trait links, Technology integration
4. **Stages table**: columns `# | Stage | Procedure | Materials | Timing`, with a header row shaded and "repeat header row" enabled for page breaks.
5. **Standards**: code + name (linked `standardIds` plus `manualStandards`).
6. **Activities, Assessment methods, Resources, Differentiation, Homework, Notes**.
7. **Footer**: "Generated by ClassHope", date, page number.

Not included by default: AI evaluation and admin notes (internal). Add an opt-in `?includeEvaluation=true` later for admins only if requested.

### 3.4 Arabic / RTL rules

- Paragraphs: `bidirectional: true`, alignment `right` (start) for Arabic.
- Runs: `rightToLeft: true`, font `Arial` or `Traditional Arabic` / `Cairo` fallback (Word falls back safely to Arial).
- Tables: `visuallyRightToLeft: true` so columns read right-to-left.
- Dates via `toLocaleDateString('ar-EG')`, same as the email localisation already in place.
- Plan content is user-written and may mix languages, so each paragraph's direction should follow the **chosen document language**, while a simple regex check (Arabic-script ratio) can flip individual cells that are clearly the other language.
- Reuse subject/category localisation helpers in `utils/emailLocalization.js` (`localizeSubject`) for names.

### 3.5 Client

- `services/lessonService.js`: `exportLessonPlanDocx(id, lang)` using `api.get(..., { responseType: 'blob' })`, then trigger download from the blob (read the filename from `Content-Disposition`).
- **Detail page** (`LessonPlanDetailPage`): "Download .docx" button with the shared `EmailLanguageControl`-style English/العربية choice (reuse `emailLanguagePreference` util, or a smaller dropdown).
- **List page** (`LessonPlanTable` row actions): small download icon (English by default, or last-used language).
- Loading state + `toast.error` on failure; i18n keys under the lesson plan namespace (en + ar).

### 3.6 Edge cases

- Very long text cells: split on newlines into separate paragraphs; preserve bullet lists (`- ` / `• ` / numbered lines) as real list items.
- Strip HTML tags if rich text was ever stored; never inject raw HTML.
- Missing class/subject (deleted): print "—".
- Large plans: build in memory is fine (<1 MB). Add a 30-second timeout guard and a rate limit (reuse `aiFeatureRateLimiter`-style limiter or a lightweight export limiter).
- Filename sanitisation (remove `\ / : * ? " < > |`, trim to 100 chars).

### 3.7 Tests

- Unit: `lessonPlanDocxService` returns a non-empty buffer starting with `PK` (zip), for en and ar, for a plan with every field empty, and for a full plan.
- Unzip the buffer with `jszip` and assert `word/document.xml` contains the title, the stage names, and `w:bidi` for Arabic.
- Controller contract test: 404 for other-school plan, 403 for a teacher exporting another teacher's plan, correct headers on success.

## 4. Feature B — CSV import of lesson plans

### 4.1 Who can import

The existing import pipeline is limited to `admin` and `department_principal`. Lesson plans are mostly written by teachers, so decide up front:

- **Recommended**: teachers can import **their own** plans (teacher = the logged-in user, forced server-side); admins/department principals can import for any teacher in scope by supplying a `teacher_email` column.
- A new route group with its own authorisation, rather than loosening the existing `authorize('admin', 'department_principal')` on all imports.

### 4.2 CSV format (one row = one lesson plan)

Header names are case-insensitive; both English and snake_case accepted.

| Column | Required | Notes |
|---|---|---|
| `title` | yes | |
| `date` | yes | `YYYY-MM-DD` (also accept `DD/MM/YYYY`; ambiguity rule documented) |
| `class` | yes | class name or code, matched within the school |
| `subject` | yes | subject name/code, matched within the school |
| `teacher_email` | admin only | defaults to uploader for teachers |
| `summary`, `description`, `previous_knowledge`, `teaching_objectives`, `learning_objectives` | no | |
| `objectives` | no | multiple objectives separated by `;` or new line |
| `vocabulary`, `character_trait_links`, `tech_integration` | no | |
| `activities`, `assessment_methods`, `resources`, `differentiation`, `homework`, `notes` | no | |
| `week_number`, `topic` | no | week 1–52 |
| `standards` | no | codes separated by `;` — matched to `Standard` by code; unknown codes become `manualStandards` with a warning |
| `stage_1_name`, `stage_1_procedure`, `stage_1_materials`, `stage_1_timing` … up to `stage_6_*` | no | repeating column groups (simple for Excel users) |
| `status` | no | forced to `draft`; ignored if supplied |

Alternative considered: two-file import (plans + stages keyed by `plan_ref`). Rejected for v1 because repeating stage columns are simpler for teachers; revisit if teachers need more than 6 stages.

### 4.3 Pipeline integration

Add `lesson_plans` as a new entity in the existing import system rather than a parallel one:

| File | Change |
|---|---|
| `services/import/importSchemas.js` | add `lesson_plans` to `normalizeEntityType`, column map/aliases, required fields, row validators |
| `services/import/importPipeline.js` | add the `lesson_plans` branch for validate (preview) and persist (commit), following the existing `subjects`/`classes` branches |
| `services/import/lessonPlanImportService.js` (new) | row → LessonPlan document mapping: resolve class/subject/teacher/standards, parse objectives and stages, build `objectives[]` with `objectiveKey` via `helpers/lessonObjectives.js` |
| `routes/importRoutes.js` | allow `lesson_plans` for teachers: add a dedicated pair `POST /lesson_plans/preview` and `/commit` registered **before** `router.use(authorize('admin','department_principal'))`, guarded by `authorize('teacher','admin','department_principal')` and `requireFeature` for lesson plans |
| `ImportTemplate` / seed | add a `lesson_plans` sample CSV (EN column headers + 2 sample rows) so the existing "Download template" flow works |
| `models/LessonPlan.js` | no schema change expected; confirm `objectiveKey` generation and tenant plugin stay intact |

Pipeline behaviour:

- **Preview** (no writes): parse, validate, return summary (`total`, `valid`, `errors`, `warnings`), first N sample rows and an `errorReportUrl` (existing error-report CSV).
- **Commit**: re-validate server-side (never trust the preview), insert valid rows only (or all-or-nothing when `strictMode`, matching existing behaviour), record an `ImportRun`.
- **Idempotency / duplicates**: duplicate key = `school + teacher + class + subject + date + normalized(title)`. Default policy: skip and warn; the existing `duplicatePolicy` option can expose `skip | create`.
- **Limits**: max 500 rows and 2 MB per file; reject other MIME types.
- **Security**: CSV-injection protection on the error-report output (prefix `= + - @` cells), strip control characters, enforce tenant `school` from `req.schoolId`, never accept `school`, `teacher` (for teachers) or `status` from the file, escape all text on render (client already escapes).

### 4.4 Client

- `LessonPlanToolbar`: "Import CSV" button next to "Create Lesson Plan" (visible to teacher / admin / department principal).
- New `ImportLessonPlansModal.jsx` modelled on `ImportStudentsModal.jsx`:
  1. Download sample template link.
  2. Choose file (drag-drop, `.csv` only, client-side size check).
  3. Parse in browser (reuse the CSV parser already used by the students import) and POST rows to `/imports/lesson_plans/preview`.
  4. Show summary cards, an errors table (row, column, message), and warnings.
  5. "Import N valid plans" → commit → success toast → refresh list via the existing `lessonSlice` thunk.
  6. "Download error report" button.
- UTF-8 handling: strip BOM; Arabic content must round-trip (test with Arabic titles and headers).
- i18n: en + ar strings.

### 4.5 Tests

- Schema/validator unit tests: missing required fields, bad date formats, week out of range, unknown class/subject, unknown standard code → warning, more than 6 stages, Arabic text, BOM, quoted commas and newlines.
- Pipeline tests: preview writes nothing; commit creates drafts with `status: 'draft'`; teacher cannot import for another teacher; duplicate skipped; cross-school class names are not resolvable.
- Contract test for authorisation on the new routes.

## 6. Risks and open questions

1. **Template**: does the school have an official lesson plan layout (logo, headings order, orientation)? If yes, replace §3.3 with that layout.
2. **Teacher import permission**: confirm teachers (not only admins) may import — see §4.1.
3. **Stage columns**: is a 6-stage cap enough?
4. **Standards**: match by `code` only, or also by name?
5. **Duplicates**: skip (default) or allow creating duplicates?
6. **Evaluation content**: confirm AI evaluation and admin notes stay out of the export.
7. **Arabic font**: Word substitutes missing fonts; Google Docs may render slightly differently. Verify both.
8. **Google Docs direct export** (future): needs `drive.file` scope, OAuth consent update, and a reconnect flow; reuse `buildLessonPlanDocx` and upload with conversion to `application/vnd.google-apps.document`.

## 7. Acceptance criteria

**Export**
- Downloading from the detail page yields a valid `.docx` that opens in Word and Google Docs with all populated sections.
- Arabic export is right-to-left, tables read right-to-left, and Arabic text is not garbled.
- A user cannot export a plan outside their scope; unauthorised requests return 403/404.

**Import**
- Sample template downloads and re-imports with zero errors.
- Preview shows accurate counts and per-row errors and writes nothing to the database.
- Commit creates only valid rows as drafts owned by the right teacher in the right school; re-uploading the same file creates no duplicates by default.
- Arabic CSVs (UTF-8 with BOM) import correctly.
